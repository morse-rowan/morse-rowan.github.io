# Paper portfolio release — September 12, 2026

Rowan explicitly requested deploying the updated local website and maintaining
clean version control. This release replaces the old hosted UI with the accepted
paper/Graphite layout, Bash name, timeline content, and inline project awards.

## Release boundaries

- Previous deployed source: `aaa34c93a8ea2fa1566c74460321f40492b1995d`, preserved by
  annotated tag `pre-paper-release-2026-09-12`.
- Local design history remains intact (`9dc0550`, `6bd4b3d`). The final supplied
  local changes are checkpointed in `620971f`.
- Release tag: `paper-release-2026-09-12`, on a merge commit whose first parent is
  the previous production `main` and second parent is `codex/graphite-ui`.
- Deployment uses the existing GitHub Actions workflow on `main`. Pages settings
  were verified through GitHub's authenticated API: `build_type: workflow`,
  custom domain `rowanmorse.me`, HTTPS enforced. No hosting or DNS change.
- No database or data migration. Existing Markdown, media, verification metadata,
  analytics ID, custom domain file, and public hash routes are preserved.
- Development comparisons remain in source but are excluded from production.
- Generated `dist/` and dependencies remain untracked. No history rewrite or
  force push. The historical `gh-pages` branch is not the deployment source.

## Deployment verification

The release push must be followed by a successful run of
[the Pages workflow](https://github.com/morse-rowan/morse-rowan.github.io/actions/workflows/deploy.yml),
then a live check of [rowanmorse.me](https://rowanmorse.me). Match the live
`index.html` asset references to the validated local build and load both public
writeup routes. Actions records the exact source SHA and deployment outcome.

## Rollback

From a clean checkout, fetch and update `main`, then revert the release merge.
This creates a new commit and preserves both the release and previous history.
Do not execute these commands unless rollback is intended.

```powershell
git fetch origin --tags
git switch main
git pull --ff-only origin main
git revert -m 1 paper-release-2026-09-12
npm ci
npm run build
git push origin main
```

Wait for the new Pages workflow run, then verify the live site. If later changes
conflict with the revert, resolve and review them before publishing. Do not
force-push `main` or change either release tag.
